# Results Agent Guide

## Required evidence

Store lightweight CSV/JSON summaries and generated charts that support reported
claims. Every record must identify commit, dataset manifest, configuration, seed,
dependency versions, hardware/device, timestamp, and protocol version.

- Never hand-edit generated metrics or benchmark results.
- Never report invented or placeholder values as results.
- Clearly distinguish smoke runs from final experiments.
- Compare models with identical eligible users and ranking candidates.
- Include Recall@10 and NDCG@10 for the GNN and accepted baseline.
- Phase 5 comparison artifacts must be generated from stored MF and
  GraphSAGE JSON files; do not hand-edit or invent those numbers.
  Phase 6 (PyG SAGEConv) must not retcon `graphsage_movielens_100k.json`
  without a measured rerun. Multi-seed SAGEConv numbers belong in
  `multiseed_gnn_vs_mf_movielens_100k.*`; do not overwrite Phase 5 files.
- Include native/reference timings and speedup with full benchmark
  context. Phase 2 timing artifacts (`sampler_timing.json` / `.md` /
  `.svg`) are generated by `sagerec_sampler_benchmark`; do not
  hand-edit those numbers. They are one-machine sampler evidence, not
  production latency or ranking quality.
- Keep checkpoints and bulky per-run logs in ignored subdirectories
  (`results/checkpoints/`). Phase 8 demo-CLI tests write temp-dir
  checkpoints only; do not commit weights or retcon 100K quality JSON.
- Phase 9/10 serving latency (`serving_latency.json` / `.md`) is written
  by `sagerec_loadtest` from a real HTTP run (both modes under
  `serving-latency-v2`). Do not hand-edit those
  numbers. They are one-machine request latency, not ranking quality.
  Serving `.npz` artifacts stay under ignored `results/serving/`.
- Phase 10 re-rank quality (`rerank_eval.json` / `.md`) is written by
  `sagerec_rerank_eval` from a real MovieLens 100K run. Do not
  hand-edit those numbers. They are single-seed implicit-MF retrieval
  plus a NumPy MLP, not GraphSAGE and not the ADR-007 leaderboard.
